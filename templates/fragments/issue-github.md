Fills `{{ISSUE_WORKFLOW}}` when project tracks issues on GitHub. Copy body below (under the rule) into AGENTS.workflow.md's `### Tracking issue` section.

---

- Candidates: `gh issue list --state all --search "<goal keywords>"` (an exact title, e.g. a slice's: `--state open --search "<title> in:title"`) — numbers only, the orchestrator never reads a body; `spec-author` reads any candidate with `bash .claude/scripts/issue-view.sh <number>`, never raw `gh issue view`. Reuse + reference its number; never open a second. Open titles (gate 4, for `spec-author`'s follow-up dedupe): `gh issue list --state open --limit 200 --json title --jq '.[].title'`.
- File, never retyped: `gh issue create --title "$(head -1 .claude/tasks/artifacts/<slug>/issue-body.md | sed 's/^# //')" --body-file <(tail -n +2 .claude/tasks/artifacts/<slug>/issue-body.md)`. Reuse: `gh issue edit <number>` with the same `--title`/`--body-file`.
- Status line (gate 2 approval, a split filed, CI green — never a body rewrite): `gh api repos/{owner}/{repo}/issues/<number> --jq .body > .claude/tasks/artifacts/<slug>/issue-live.md`, `sh .claude/scripts/issue-body.sh <slug> --status .claude/tasks/artifacts/<slug>/issue-live.md > .claude/tasks/artifacts/<slug>/issue-status.md`, `gh issue edit <number> --body-file .claude/tasks/artifacts/<slug>/issue-status.md`. Comment (a kept spec change): `gh issue comment <number> --body-file .claude/tasks/artifacts/<slug>/issue-comment.md`. Follow-up (gate 4): `gh issue create` from `follow-up-<k>.md` exactly as the file command above, after `Found in #<number>` is appended to it.
- Close: the PR's `Closes #<number>` line (appended by `pr-body.sh`) closes it on merge — nothing to do.
